# 2026-11-22 代码复查

本次复查覆盖整个仓库的自动检查，并人工检查登录认证、登录记录与通知、账号修改、订阅生成、节点与分组操作、导入导出、模板文件操作、安装更新及构建流程。前端业务页面与数据请求一并检查；示例组件、类型声明及生成的静态资源以类型检查、构建和依赖分析为主。本记录不是对所有输入和部署方式均无缺陷的保证。

## 本次已修复

1. **跨计时边界漏报登录失败**：使用固定内存保存最近五次失败时间，按最近五分钟统计，持续失败时每五分钟最多提醒一次。
2. **重复保存设置丢提醒**：相同配置不再使旧队列失效；首次保存仍持久化配置，后续相同保存不写文件。
3. **队列恢复后继续漏报**：队列满时不启动失败提醒冷却。配置实际变更导致的排队消息取消单独计数，旧配置的在途发送错误不再覆盖新配置状态。
4. **认证白名单范围过宽**：公开接口按路径和请求方法匹配，避免使用相同前缀的后台接口被放行；认证头增加大小限制，避免对大量分隔符无限分割分配内存。
5. **客户端订阅链接未区分格式**：分别生成明确带 `client=v2ray`、`client=clash`、`client=surge` 的链接，不再依赖下载工具的 User-Agent 猜测格式。
6. **节点保存失败清空输入**：失败后保留弹窗及输入，允许修正或重试；分组筛选状态下选择其它节点时，从完整节点列表读取其原分组。
7. **修改密码时擅自去掉空格**：保留密码原值，只对账号去掉首尾空格。
8. **模板写入失败损坏旧文件**：改为同目录临时文件完成写入和关闭后再替换；保存失败保留原模板，管理写操作串行处理。增加 Linux 子进程短写测试，模拟磁盘写入失败而不填满磁盘。
9. **协议编码参数丢失**：修复 VLESS、Trojan、Hysteria、Hysteria2 的 IPv6 地址编码；保留 ALPN、VLESS serviceName/mode、Hysteria2 SNI/混淆参数，识别 peer 别名。
10. **分组辅助方法错误**：修复有效分组改名仍报错、重用已有分组时丢失 ID，以及查找失败仍继续关联/清理的问题；这些修复不新增后台接口。
11. **依赖与构建**：更新 Go 网络库；升级有告警的前端运行依赖、移除未使用的 `xlsx` 和作为运行依赖引入的旧 pnpm；固定构建工具与允许执行的安装脚本。新镜像及发行版只嵌入本次生成的前端资源，避免残留旧版本组件。
12. **26 项开发工具依赖告警**：升级 Vite、UnoCSS 与 JSX 插件；移除依赖旧 `svg-baker` / PostCSS 5 的 SVG 插件，以受维护的 SVGO 和仓库内小型插件保留原图标接口；为间接依赖设置修复版本约束。全部前端依赖扫描告警已降为 0，没有使用忽略告警的方式。

## 仍保留的限制

- 漏洞扫描结论对应本次锁定的依赖与当时的漏洞数据库；零告警不能保证没有尚未披露的缺陷。
- 登录记录只覆盖账号密码登录；复用已登录会话、订阅请求和被 Cloudflare 提前拦截的扫描不会生成登录记录。本功能提供检测与通知，不代替登录限速或访问控制。
- 真实 IP 依赖部署时正确配置可信代理，并限制后端绕过代理的入口；客户端自身使用代理/VPN 时记录的是其出口 IP。
- 20 条登录记录和通知队列均在内存；服务重启会清空，网络失败、队列满及实际配置变更可能导致通知未送达，后台显示相关数量。
- 原有订阅访问记录功能仍会更新业务数据库，它与新增的内存登录记录是两套功能。普通文件日志可关闭，但不能据此理解为整个应用完全不写磁盘。
- 本次修改并提交源代码，不自动升级 N1。真实 Telegram 配置、代理地址和凭据保留在部署设备，不写入公开仓库。
